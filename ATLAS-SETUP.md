# MongoDB Atlas Setup for Portfolio Analytics

The portfolio server (`server.fg`) writes tracker events to a MongoDB collection. For local development it talks to `mongod` on `127.0.0.1:27017`; in production it talks to MongoDB Atlas. This guide walks through provisioning Atlas and wiring the connection string into the Docker deploy.

> **About the `mongodb+srv://` form:** the Flow-Wing `mongo` module is built against `mongo-c-driver 2.3.0` with `ENABLE_SRV=OFF` (avoids dragging in `c-ares` as a system dep). Atlas's default "Connect" string is `mongodb+srv://…` and will NOT resolve. **You must use the legacy non-SRV form** (`mongodb://host1,host2,host3/…?ssl=true&replicaSet=…&authSource=admin`). Atlas exposes it under **Connect → "Shell" → legacy connection string**.

---

## 1. Create an Atlas account & free cluster

1. Sign up at https://www.mongodb.com/cloud/atlas/register (free, no card).
2. Click **"Build a database"** → choose **M0 (Free shared cluster)**.
3. Pick a cloud + region close to where the portfolio will be deployed (where the Hostinger/etc. VPS lives — pick the closest AWS / GCP / Azure region).
4. Cluster name: keep default or rename to e.g. `portfolio-prod`.
5. Wait ~3-5 min for the cluster to provision.

## 2. Create a database user

Atlas → **Security → Database Access → "Add New Database User"**.

- **Authentication method:** Password.
- **Username:** `portfolio_writer` (or any short identifier).
- **Password:** click **"Autogenerate Secure Password"** → copy it now, save in 1Password / your password manager. You won't see it again easily.
- **Database User Privileges:** **"Add Built-in Role" → "readWrite"** → set the database to `portfolio` only (not `admin`). Least-privilege: the writer can read/write `portfolio.events` but cannot drop databases, manage users, etc.
- Save.

## 3. Allow network access

Atlas → **Security → Network Access → "Add IP Address"**.

Pick ONE of:
- **(easiest)** "Allow access from anywhere" → `0.0.0.0/0`. Fine because Atlas requires TLS + username/password.
- **(tightest)** Add only the deploy server's public IP. Find the IP by SSH-ing to the VPS and running `curl ifconfig.me`.

## 4. Get the legacy (non-SRV) connection string

Atlas → **Database → cluster `portfolio-prod` → "Connect" button**.

The default flow shows you `mongodb+srv://…` — **don't use this**. Instead:

- In the "Connect to your cluster" panel, find **"Shell"** (or "Connect using the Shell").
- Look for **"Legacy connection string"** (sometimes under "Show secondary options" or similar). It looks like:
  ```
  mongodb://portfolio_writer:<password>@portfolio-prod-shard-00-00.xxxxx.mongodb.net:27017,portfolio-prod-shard-00-01.xxxxx.mongodb.net:27017,portfolio-prod-shard-00-02.xxxxx.mongodb.net:27017/?ssl=true&replicaSet=atlas-xxxxxx-shard-0&authSource=admin&retryWrites=true&w=majority
  ```
- Replace `<password>` with the password you saved in step 2 (URL-encode any `@`, `:`, `/`, `?`, `&`, `#`, `%` characters — most autogenerated Atlas passwords are URL-safe already).
- Replace the default `myFirstDatabase` (if Atlas inserted one) with nothing — the binding writes to `portfolio.events` directly via `getCollection("portfolio", "events")`.

Save this full URI; it's what you'll pass to the server as `arg 1`.

If you cannot find the legacy form in the Atlas UI (the wording moves around between Atlas releases), the alternative is to read it from `mongosh` after running `mongosh "<srv-uri>"` once and inspecting `db.getMongo().s.uri` — but the simplest fix is to expand "Show secondary options" / "Advanced" in the connect dialog.

## 5. Generate an admin token

The portfolio's admin dashboard lives at `/admin/<token>`. Pick a long random token:

```sh
openssl rand -base64 32 | tr -d '/+=' | head -c 32
```

Save this too. You'll bookmark `https://kushagra.frii.site/admin/<token>` for yourself.

## 6. Plug the URI + token into the Docker deploy

The portfolio's setup script (the bash you pasted earlier with the `Dockerfile.portfolio`) currently runs:

```dockerfile
CMD ["./portfolio-server"]
```

with no args. We need to pass `MONGO_URI` and `ADMIN_TOKEN` as positional args. Two ways:

### Option A — bake into the image (simplest, OK for one-server deploys)

Edit `Dockerfile.portfolio`'s last line:

```dockerfile
CMD ["./portfolio-server", "<your-mongo-uri>", "<your-admin-token>"]
```

Rebuild + redeploy. **Downside:** the URI ends up in the image. Keep the image private.

### Option B — env vars + entrypoint (cleaner)

Edit `Dockerfile.portfolio`:

```dockerfile
# replace the existing CMD line with:
ENTRYPOINT ["sh", "-c", "./portfolio-server \"$MONGO_URI\" \"$ADMIN_TOKEN\""]
```

Then in `docker-compose.yml`, under `portfolio-app`:

```yaml
portfolio-app:
  build:
    context: .
    dockerfile: Dockerfile.portfolio
    args:
      - CACHEBUST=${CACHEBUST_VAR:-1}
  container_name: portfolio-app
  restart: unless-stopped
  read_only: true
  cap_drop:
    - ALL
  environment:
    - MONGO_URI=${MONGO_URI}
    - ADMIN_TOKEN=${ADMIN_TOKEN}
  volumes:
    - /var/run/docker.sock:/var/run/docker.sock
    - /tmp/submissions:/tmp/submissions
  depends_on:
    - flowwing-sandbox
```

On the host, create `/home/<user>/flowwing-gateway/.env`:

```
MONGO_URI=mongodb://portfolio_writer:<password>@portfolio-prod-shard-...
ADMIN_TOKEN=<your-32-char-token>
```

Compose reads `.env` automatically. `chmod 600 .env`. **Never** commit this file to git (already covered by `.gitignore`).

## 7. Verify

Restart the stack: `sudo docker compose up -d --force-recreate portfolio-app`.

Inspect logs:
```sh
sudo docker compose logs portfolio-app | head -10
```

Expected first few lines:
```
Vortex server listening on port 8080
mongo connected: mongodb://portfolio_writer:***@portfolio-prod-shard-...
The Career Compiler — served by Flow-Wing at http://127.0.0.1:8080
```

If you instead see `mongo connect failed:` followed by:
- `No suitable servers found` → URI is wrong or network access not opened (step 3).
- `Authentication failed` → wrong username/password.
- `Invalid URI scheme` → you accidentally used `mongodb+srv://` (re-read the box at the top).

Then visit `https://<your-portfolio-domain>/` and click around. After a few seconds, open `https://<your-portfolio-domain>/admin/<token>` — events should be appearing.

## 8. Indexes (do once, after first events flow)

For query performance once the collection grows, create these indexes via Atlas's **Data Explorer → portfolio.events → Indexes → "Create Index"**:

```js
{ ts: -1 }                  // newest-first reads (used by the dashboard)
{ type: 1, ts: -1 }         // filter by type, sorted by recency
{ session: 1, ts: -1 }      // session-replay grouping
```

These can also be created from a local `mongosh` session pointed at the Atlas URI:

```sh
mongosh "<atlas-uri>"
use portfolio
db.events.createIndex({ ts: -1 })
db.events.createIndex({ type: 1, ts: -1 })
db.events.createIndex({ session: 1, ts: -1 })
```

## 9. Local development (mac)

For local dev, no Atlas needed. Just keep `mongod` running:

```sh
brew services start mongodb-community
```

Then run the server with no args — it falls back to `mongodb://127.0.0.1:27017` and dev-admin-token:

```sh
flowwing server.fg -o ./career && ./career
# admin: http://127.0.0.1:8080/admin/dev-admin-token
```

## 10. If you want to switch back to `mongodb+srv://` later

Rebuild Flow-Wing's `mongo-c-driver` dep with `-DENABLE_SRV=ON` (in `cmake/deps_builder/CMakeLists.txt`, in the `mongo_c_driver_external` block) and add a `c-ares` dep above it (also via `ExternalProject_Add`, version 1.27+). Then SRV resolution will work and Atlas's default URI is fine. Out of scope for this initial deploy.
